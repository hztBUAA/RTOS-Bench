# feiteng4rtos Template Overlay

This directory contains the hand-maintained files that make the validated
Ruihua Feiteng sample project build and run RTOS-Bench.

Copy these files into a working Ruihua/ReWorks sample project based on:

```text
C:\rtos\6.1.1-ARM\workspace\feiteng4rtos
```

Do not treat this as a full ReDe project export.  Files such as
`makefile.conf`, `gnuaarch64/FTE2000_SMP-64/makefile`, and generated
`subdir.mk` files are IDE/BSP generated and should come from the validated
sample project or be regenerated by ReDe.

## Files

```text
feiteng4rtos-template
├── usrInit.c
├── usrArgs.h.example
├── gnuaarch64\
│   └── user.mk
├── les\
│   └── bench_init.c
└── rtosbench_port\
    ├── rtosbench_boot.c
    ├── ruihua_workloads.c
    └── sched_workloads_stub.c
```

## Required Adjustments

- Update `gnuaarch64/user.mk` if your RTOS-Bench checkout is not at
  `C:/Users/hzt/yihui-workspace/rtos-bench/RTOS-Bench`.
- Choose the correct `GEM0_IPV4_ADDR` in `usrArgs.h`:
  - campus network: `192.168.31.210`
  - direct PC-to-board: `192.168.2.100`
- Keep `rtosbench_port` in the project.  It registers workloads and provides
  the boot smoke entry used by `usrInit.c`.
- Keep `les/bench_init.c` as a wrapper to the repository-maintained realtime
  implementation when validating full realtime/stress modules.
