# 锐华(ReWorks)龙芯派 —— RTOS-Bench 编译 / 部署 / 运行指南(ReDe IDE 版)

> 适用对象:在 **锐华 ReWorks + 龙芯派(LoongArch64,LS2K1000 系列)** 上构建并运行 RTOS-Bench 的同学。
> **本文面向"没有配置命令行工具链"的情况**——你**不需要**自己在 PATH 里配 `loongarch64-elf-gcc`,
> 全程在 **ReDe IDE** 里点按钮构建,IDE 会用它自带的工具链替你跑 `gnu_make`。
> 内容基于仓库 **最新 `origin/main`**,所有文件名/选项以 `main` 为准。

---

## 0. 结论(TL;DR)

1. 在 **ReDe IDE** 里:`文件 → 新建 → 可下载工程`,**选龙芯 BSP**(`loongarch2k1000la_64bits_smp_bsp_config`)。
2. 把仓库 `platforms/ruihua/rtosbench-project-template/` 下的文件拷进新建工程目录。
3. 把 `makefile.local.example` 复制成 `makefile.local`,改三行:`REDE_HOME` / `RTOSBENCH_SRC` / **`ARCH := loongarch64`**。
4. 在 IDE 里 **Build Project**(IDE 自动调 `gnu_make all`,自带工具链)。产物:`gnuloongarch64/rtosbench.out`。
5. **下载前自检**(用 SDK 自带工具,给全路径,见第 5 节):`readelf -h` 看到 `LoongArch`、`nm` 看到 `T ekf_bench_run_quick`。
6. 通过 IDE 的"下载"功能下发到板子;或在板端 `reworks> ld "rtosbench.out"`。

> **为什么必须走这套模板工程**:它的 `Makefile` 在 `ARCH=loongarch64` 下会自动加上龙芯加载器必需的代码模型选项
> (`-fno-plt`、`-Wa,-mla-local-with-abs`、`-Wa,-mla-global-with-abs`、`-G0`、`--oformat=elf64-loongarch`)。
> 这些选项**飞腾派那套 `user.mk` 里没有**,所以拿飞腾模板编龙芯必然报 `R_LARCH_* relocation failed`。

## 1. 背景:之前两次报错分别是什么(帮助理解)

`reworks>` 下的 `ld "xxx.out"` 不是编译器,而是 ReWorks 板端的**运行时加载器**:把模块下载进内核,做
**装载区段 → 解析符号 → 按运行地址回填(重定位)**。两次报错是这条链上的两层:

| 报错 | 含义 | 根因 | 状态 |
|---|---|---|---|
| `Unresolved symbol: sched_*_quick_exec` | 调度 wrapper 符号没定义 | `sched_compute_wrappers.c` 没进编译清单 | ✅ 已在 `main` 修复 |
| `Unresolved symbol: ekf_bench_run_quick` + `R_LARCH_SOP_* relocation failed ... (check compiler flags!)` | 龙芯加载器搞不定模块里的重定位 | 编译时**缺龙芯代码模型选项** | 本文解决 |

第二类里 `ekf_bench_run_quick` 显示"未找到",**不是函数没实现**(它在 `workloads/EKF/ekf_bench.cpp:174`),
而是承载它的引用点重定位失败、加载器无法把引用绑定到定义,于是报成 "Unresolved"。

> **⚠️ 首要排查(最常见的真因):先确认符号到底在不在 `.out` 里。**
> 实践中 `Unresolved symbol: ekf_bench_run_quick` 最常见的原因,其实是**这个函数压根没编进 `.out`**
> (例如某次重构只把"调用方"推上仓库、"定义方"漏推,或源文件没进构建清单)。这种情况下,龙芯还会
> **连带**报一片 `R_LARCH_SOP_* relocation failed`——加载器无法给一个未解析符号回填地址,龙芯一次取址
> 又拆成多条重定位,所以一个缺失符号会炸出一串重定位错。
> **所以先用第 5 节的 `nm` 看符号是 `T`(已定义)还是 `U`/查不到,再决定是"补符号"还是"调 flag"。**
> (本仓库 `ekf_bench_run_quick` 的缺失已在 `main` 修复;请同事务必 `git pull` 到最新再编。)

## 2. 目录结构

### 2.1 仓库里你要用到的

```
RTOS-Bench/
├── generator/                              # 框架核心 + 平台抽象
│   ├── test_schedule.c                     # 可调度性测试主逻辑
│   ├── test_schedule/
│   │   ├── sched_workloads.c               # wrapper 注册表
│   │   ├── sched_compute_wrappers.c        # ← 计算类 wrapper 实现(之前缺的就是它)
│   │   ├── sched_mqtt_wrapper.c / sched_modbus_wrapper.c
│   ├── ruihua_entry.c                       # ReWorks shell 入口(rtbench_*)
│   └── platform/ruihua/                     # 锐华平台垫片
├── workloads/                               # 真实算法核心(被 wrapper 调用)
│   └── EKF/ekf_bench.cpp                    # ← ekf_bench_run_quick() 定义在这
└── platforms/ruihua/
    └── rtosbench-project-template/          # ★ 本文用的"可下载工程"模板
        ├── .project                         #   ReDe/Eclipse 工程描述(告诉 IDE 用 gnu_make 构建)
        ├── Makefile                         #   编译入口:源码清单 + 多架构 + 龙芯专属选项
        ├── makefile.conf                    #   各架构 BSP/runtimelib/链接选项(含龙芯 -G0 / --oformat)
        ├── makefile.local.example           #   本机配置示例 → 复制成 makefile.local
        └── .gitignore                       #   忽略 makefile.local 和 gnu*/ 产物
```

各文件职责(来自 README1):
- **`.project`**:工程描述,告诉 IDE "这是 `rtosbench` 工程、用 builder 调 `gnu_make`"。不列源码、不放本机路径。
- **`Makefile`**:真正的编译入口,维护源码清单、宏、include、架构参数、链接规则。
- **`makefile.conf`**:锐华板级/runtimelib/SDK 头文件配置,一般不用改。
- **`makefile.local`**(你创建):放**你本机**的安装路径、源码路径、**构建架构**。
- 路径变量优先级:**命令行 > `makefile.local` > `Makefile` 默认值**。本机差异只写 `makefile.local`,不要改 `Makefile`/`makefile.conf`。

### 2.2 IDE 工程目录(拷贝后,在锐华 workspace 下)

```
<REDE_HOME>/workspace/rtosbench/      # 例如 C:/rtos/6.1.1-Loongarch/workspace/rtosbench
├── .project                          # 从模板拷入
├── Makefile                          # 从模板拷入
├── makefile.conf                     # 从模板拷入
├── makefile.local                    # 你新建(改本机路径 + ARCH)
└── gnuloongarch64/                   # 构建后自动生成
    └── rtosbench.out                 # ← 最终产物
```

> RTOS-Bench 源码**不需要**拷进工程;`Makefile` 通过 `RTOSBENCH_SRC` 指向你 clone 的仓库,直接从那里编译。

## 3. 准备

1. **ReDe IDE + 龙芯 SDK** 已安装(即 `REDE_HOME`,例如 `D:/6.1.1-Loongarch`)。SDK 自带龙芯工具链,**无需另配命令行 PATH**。
2. **本仓库**已 `git pull` 到最新 `main`(确保含 `sched_compute_wrappers.c` 的构建修复)。
3. 知道龙芯 BSP 名:`loongarch2k1000la_64bits_smp_bsp_config`(`makefile.conf` 里的默认值,可按你 SDK 实际名调整)。

## 4. 在 ReDe IDE 里构建(核心步骤)

### 4.1 新建可下载工程,选龙芯 BSP
ReDe IDE → `文件 → 新建 → 可下载工程` → 选择**龙芯对应的 BSP**(`loongarch2k1000la_64bits_smp` 那一类)。
> 关键:BSP 必须选龙芯的,不要选飞腾/FTE2000。BSP 决定了底层 CSP 库和工具链。

### 4.2 拷贝模板文件
把仓库 `platforms/ruihua/rtosbench-project-template/` 下的
`.project`、`Makefile`、`makefile.conf`、`makefile.local.example`
拷到新建工程目录,例如:
```
C:/rtos/6.1.1-Loongarch/workspace/rtosbench
```

### 4.3 配置 makefile.local(决定架构,务必正确)
在工程目录里把 `makefile.local.example` 复制成 `makefile.local`,改成你本机实际值:
```makefile
# 锐华龙芯 IDE/SDK 安装根目录
REDE_HOME := D:/6.1.1-Loongarch

# 你 clone 的 RTOS-Bench 仓库根目录
RTOSBENCH_SRC := D:/workspace/RTOS-Bench

# 目标架构 —— 龙芯必须是这个
ARCH := loongarch64
```
> `makefile.local` 已被 `.gitignore` 忽略,可放心写绝对路径。
> **`ARCH := loongarch64` 是关键**——它让 `Makefile` 走龙芯分支、加上那 5 个代码模型选项。

### 4.4 构建
在 IDE 里打开 `rtosbench` 工程 → **Build Project**(干净重编用 Clean Project 再 Build)。
IDE 会自动执行 `gnu_make all`,用它自带的龙芯工具链编译——**你不用在命令行配任何东西**。

> 如果 IDE 的构建配置(`项目属性 → C/C++ 构建`)里能选架构,确认与 `makefile.local` 的 `ARCH` 一致即可;
> 以 `makefile.local` 的 `ARCH := loongarch64` 为准最稳。

### 4.5 产物
```
<工程目录>/gnuloongarch64/rtosbench.out
```

### 4.6 这套在 ARCH=loongarch64 下自动加的选项(你无需手动加)

| 选项 | 来源 | 作用 |
|---|---|---|
| `-mabi=lp64d -march=loongarch64 -mstrict-align` | Makefile | 龙芯 64 位 ABI/架构 |
| `-fno-plt` | Makefile | 不走 PLT(加载器不支持) |
| `-Wa,-mla-local-with-abs` / `-Wa,-mla-global-with-abs` | Makefile | `la` 取址用**绝对寻址**(避免重定位溢出) |
| `-G0` | makefile.conf | 不用 GP 相对小数据区 |
| `--oformat=elf64-loongarch` | makefile.conf | 链接输出格式 |
| `-DRTOSBENCH_USE_MANUAL_WORKLOAD_REGISTRATION` | Makefile | 手动注册 workload |

## 5. 下载前自检(用 SDK 自带工具,无需配 PATH)

你没配命令行工具链,但 **SDK 里本来就带** `nm`/`readelf`。两种用法,任选其一:

- **用全路径调用**(把下面路径换成你 SDK 的实际位置;参考飞腾是 `tools/build/gnuaarch64/bin`,龙芯对应 `gnuloongarch64`):
  ```
  D:\6.1.1-Loongarch\tools\build\gnuloongarch64\bin\loongarch64-elf-readelf.exe -h gnuloongarch64\rtosbench.out
  D:\6.1.1-Loongarch\tools\build\gnuloongarch64\bin\loongarch64-elf-nm.exe       gnuloongarch64\rtosbench.out
  ```
- 或者直接在 **IDE 的构建控制台 / 内置终端**里跑(IDE 已经把工具链放进它的环境了),命令同下、不用写全路径。

**校验 1 —— 架构必须是龙芯**
```
loongarch64-elf-readelf -h gnuloongarch64/rtosbench.out | findstr Machine
# 期望:Machine:  LoongArch       （若是 AArch64/ARM 就是架构/BSP 选错了）
```

**校验 2 —— 关键符号都已定义(T)**
```
loongarch64-elf-nm gnuloongarch64/rtosbench.out | findstr "ekf_bench_run_quick sched_ekf_quick_exec"
# 期望两个都是 "T 符号名"（T=已定义）。
# 若是 "U" 或查不到 → 对应源文件没编进来（检查最新 main、Clean 重编、makefile.local 路径）。
```
- `sched_ekf_quick_exec` 来自 `sched_compute_wrappers.c`
- `ekf_bench_run_quick` 来自 `workloads/EKF/ekf_bench.cpp`
- 两个都为 `T`,说明 wrapper 层和算法核心层都进来了。

> Windows 下用 `findstr` 代替 `grep`;若在 IDE 的类 Unix 终端里,用 `grep` 即可。

## 6. 部署到板子 + 运行

**下载**(二选一):
- **IDE 下载**:这是"可下载工程",用 IDE 的下载/调试功能把 `rtosbench.out` 下发到目标板;或
- **板端手动加载**:把 `rtosbench.out` 传到板子可访问路径后,在板端:
  ```text
  reworks> ld "rtosbench.out"
  ```

**加载成功**时不应再出现任何 `Unresolved symbol` 或 `Relocation ... failed`。
然后调用入口命令(定义在 `generator/ruihua_entry.c`):
```text
rtbench_help
rtbench_list
rtbench_test_schedule_quick        # 快速冒烟
rtbench_test_schedule_cycles3      # 完整可调度性测试,结尾应有 Final Score: 100.00 / 100
```

> 备注:锐华飞腾派"验收通过"的做法是把 RTOS-Bench **静态链进启动镜像** `reworks.elf`(见 `platforms/ruihua/README.md`),
> 而非 `ld` 独立 `.out`。龙芯上若独立 `.out` 仍不稳定,可考虑同样改成"链进镜像"的方式。

## 7. 报错对照表

| 报错 | 真实含义 | 处理 |
|---|---|---|
| `Unresolved symbol: sched_*_quick_exec` | wrapper 实现没编进来 | 用最新 `main`;Clean + Build;`nm` 应见 `T sched_*_quick_exec` |
| `Unresolved symbol: ekf_bench_run_quick` + `R_LARCH_* relocation failed` | **不是没实现**;龙芯重定位失败 | 确认 `makefile.local` 是 `ARCH := loongarch64` 并走本模板;Clean 重编;`nm` 确认 `T` |
| `R_LARCH_SOP_* ... overflow / not within section (check compiler flags!)` | 加载器搞不定默认代码模型 | 同上:确认走的是本模板(自动带 `-fno-plt -Wa,-mla-* -G0 --oformat`),不是飞腾 `user.mk` |
| `readelf -h` 显示 `Machine: AArch64` | BSP/架构选错了 | 新建工程时选**龙芯 BSP**;`makefile.local` 设 `ARCH := loongarch64`;Clean 重编 |
| 改了还报错 | 用了旧 `.o`/旧 `.out` | 一定 Clean Project;确认下载的是**刚生成**的 `gnuloongarch64/rtosbench.out` |
| `cpu.h`/`csp_specs` 找不到、`int_cpu_lock`/`context_switch` undefined | 龙芯 CSP/BSP 配置缺失 | 确认新建工程时选了正确龙芯 BSP;必要时找锐华同事补齐龙芯 CSP 组件 |

## 8. 可选:命令行构建(仅当 IDE 提供了 make 环境)

如果哪天你能用 IDE 自带的 `gnu_make`(它在 SDK 里),等价命令是:
```bat
cd /d C:\rtos\6.1.1-Loongarch\workspace\rtosbench
gnu_make ARCH=loongarch64 clean all
```
本质和 IDE 的 Build Project 一样,**仍然不需要你自己装/配工具链**,用的是 SDK 自带的 `gnu_make` 和龙芯交叉工具。
