#### （一）框架层在“绑核”接口的上的统一性
之前让厂商提供了一个绑核函数的实现，并且进行封装，需求如下（它们具体位于les/cpu_set.c以及cpu_set.h）：
```
为完成多核性能测试，还需要确保提供一个符合GNU/Linux规范的接口：
1.	pthread_setaffinity_np —— (将线程绑定到核心) 
并同时提供数据类型与宏：
2.	cpu_set_t —— （CPU 亲和性掩码） 
3.	CPU_ZERO(cpu_set_t *set) —— （初始化掩码，将所有位清零） 
4.	CPU_SET(int cpu, cpu_set_t *set) —— （将指定的 CPU 添加到掩码中） 
```
不知道对于这些函数、变量或宏，框架层是否有统一的调用方式？

#### （二）单核测试和多核测试分开运行
单核测试和多核测试，前者需要在只开启单核的板子上运行，后者需要至少开启2个核心。
目前的rtbench test-realtime --multicore选项是先跑一遍单核测试，再跑一遍多核测试，还是应该能够分开运行，比如test-realtime只进行单核测试，然后test-realtime --multicore只进行多核测试。

#### （三）系统调用延迟开关
目前（在les/les.h中）有一个开关：
```c
#define LES_NO_GETPID 0
```
这是一个定义“单核实时性能-系统调用是否开启”的开关，希望能把这个开关做成一个全局的开关。
