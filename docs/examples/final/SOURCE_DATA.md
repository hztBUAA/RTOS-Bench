## 2. 每个板卡块的位置

每个板卡占 20 行。以 B 列为「调度性能」的那一行为锚点。

```
块起始行 = 调度性能行 − 14
```

| 内容 | 位置（相对块起始行） | 说明 |
|---|---|---|
| 板卡名 | 起始行 G 列 → H 列 → A 列 | 取第一个非空且不以「表 1」开头 |
| 调度得分 | 调度行 E 列 | 100×(1−MR) |
| 平均错失率文本 | 调度行 F 列 | 形如「平均截止时间错失率 0.042」 |
| 梯度错失率 | I 列，调度行后 0–6 行内 | 文本以「30%」开头，共 8 行 |
| 典型负载实测 | 起始行+9 .. +12，F 列 | 单位 ms，4 类各一行 |
| 典型负载基准 | 起始行+9 .. +12，G 列 | 单位 ms |
| 基础实时得分 | 起始行+13，E 列 | 已是 min-max 后的加权分 |
| 功耗得分 | 起始行+15 .. +18，E 列 | 4 项 |
| 功耗实测 | 起始行+15 .. +18，F 列 | 单位 J |
| 调度 20 项 | K 列指标名，L–O 四场景 | 8 个操作 × 最多 4 场景 |
| 多核指标 | Q 列指标名，R–U 四个并发度 | 1/2/4/8 |

多核明细包含：

- 存取：`rd`、`wr`、`cp`、`frd`、`fwr`、`fcp`、`memset`、`memcpy`
- 系统服务：`任务间通信`、`创建与删除`
- 通信：`同核通信`、`异核通信`

## 3. 算法链路

```
第一手 Excel
  → SSOT JSON（excel_to_result_json.py）
  → 算分输入（ssot_to_score_json.py）
  → score_caculate.py（博函 Base_RT 修复版）
  → 60 保底（score_seven_workload.py）
  → 7/9 负载总分
```

### 公式

```
总分 = 0.2×F + 0.3×RT + 0.4×T + 0.1×P
RT   = 0.5×基础实时 + 0.5×调度
T    = 四类负载均值
P    = 四项功耗均值
F    = 60（占位）
```

- 只对 min-max 分项做 `60 + 0.4×原分`：基础实时、T 的四类、P。
- 调度分 = 100×(1−平均错失率)，不做保底。
- 平均错失率 = 总错失 job / 总 job：7 负载 168，9 负载 216。
- 基础实时：上下文 10%、中断 10%、系统服务 40%、多核 40%。哪吒为单核，排除多核并重归一化。

## 4. 对方更新 Excel 后注意

1. **页签名**：四个厂商页签是否改名。
2. **块行数**：每个板卡是否仍为 20 行。插入或删除行会让偏移全部错位。
3. **锚点**：「调度性能」是否仍在 B 列。
4. **梯度单元格**：是否仍在 I 列、文本是否仍以「30%」开头。
5. **负载与功耗行**：偏移 +9–+12、+15–+18 是否变化。
6. **多核表**：是否仍从 Q 列开始，四个并发度是否仍是 R–U。
7. **哈希**：与上表比对，变化即需重新生成。

改完后运行一次，检查块数：

```bash
python3 utils/build_reports.py source/9load_raw.xlsx --workloads 9 -o /tmp/check9
python3 utils/build_reports.py source/7load_raw.xlsx --workloads 7 -o /tmp/check7
```

两份都应输出 15 块板。数量不对，说明布局被改过，需要先修解析再算分。

- 欧拉两块板没有原始明细，基础实时与 T 沿用云端汇总值。
